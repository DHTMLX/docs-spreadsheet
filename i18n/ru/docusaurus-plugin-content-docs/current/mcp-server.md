# MCP-сервер DHTMLX Spreadsheet: формулы, форматирование и API для работы с листами {#dhtmlx-spreadsheet-mcp-server-formulas-formatting-and-sheet-apis}

Приложения на основе [DHTMLX Spreadsheet](/) требуют точной работы с [формулами](/functions/), [форматированием ячеек](/data_formatting/), [загрузкой данных](/loading_data/) и [управлением листами](/working_with_sheets/). Ничего из этого не почерпнуть из данных, заученных при обучении модели: нужны актуальный синтаксис формул, методы API, которые Spreadsheet предоставляет уже сегодня, и параметры конфигурации, которые с тех пор не менялись.

MCP-сервер DHTMLX решает эту проблему, предоставляя ассистенту прямой доступ к актуальной справочной информации по Spreadsheet прямо в процессе работы. Направьте его к [форматам чисел](/number_formatting/), [Sheet Manager API](/api/overview/sheetmanager_overview/) или [загрузке данных](/loading_data/) — и он сверится с актуальной документацией, прежде чем сгенерировать хотя бы одну строку кода.

### Конечная точка MCP {#mcp-endpoint}

~~~jsx
https://docs.dhtmlx.com/mcp
~~~

:::note
MCP-сервер DHTMLX охватывает все основные продукты DHTMLX, а не только DHTMLX Spreadsheet. Одна и та же конечная точка и инструкции по настройке подходят независимо от того, с каким компонентом DHTMLX вы работаете.
:::

## Возможности MCP-сервера для Spreadsheet {#mcp-server-coverage-for-spreadsheet}

Каждая страница документации DHTMLX Spreadsheet доступна для поиска через MCP-сервер. Типичные сценарии использования:

- Поиск актуального API для [методов](/api/overview/methods_overview/), [событий](/api/overview/events_overview/) и [свойств](/api/overview/properties_overview/) Spreadsheet, включая сигнатуры и возвращаемые типы.
- Генерация готового к запуску кода [инициализации](/initialization/) и [конфигурации](/configuration/) Spreadsheet на основе описания того, что вам нужно.
- Изучение [форматов чисел](/number_formatting/) (общий, числовой, процентный, денежный, дата, время и другие) и понимание того, как задавать пользовательские маски форматирования.
- Работа с [формулами и функциями](/functions/): поиск поддерживаемых функций, понимание синтаксиса формул и использование API вычислений.
- Настройка [столбцов и строк](/work_with_rows_cols/), включая задание ширины, скрытие и закрепление.
- Применение [форматирования](/data_formatting/) и стилей к ячейкам и диапазонам, включая цвет текста, выравнивание, границы и цвет фона.
- Обработка [событий Spreadsheet](/handling_events/) для реакции на изменения значений, выбор ячеек, действия редактора и взаимодействия на уровне листа.
- Изучение [поддержки нескольких листов](/working_with_sheets/), [загрузки и экспорта данных](/loading_data/) (JSON и Excel), а также интеграции с фреймворками, такими как [React](/react/), [Vue](/vuejs_integration/), [Angular](/angular_integration/) и [Svelte](/svelte_integration/).

## Как ассистент отправляет запросы к MCP-серверу {#how-the-assistant-queries-the-mcp-server}

Каждый запрос к MCP-серверу DHTMLX проходит через конвейер Retrieval-Augmented Generation (RAG), построенный на основе Model Context Protocol (MCP). В зависимости от того, что именно требуется, сервер передаёт запрос в один из двух сценариев: *Search*, который подбирает подходящие страницы справочника для ассистента, или *Inference*, который сам читает эти страницы и формирует ответ. Перед этим ассистент определяет, какая часть запроса требует обращения к документации, а с остальным справляется самостоятельно.

Рассмотрим в качестве примера запрос: *«Как настроить DHTMLX Spreadsheet, чтобы он получал актуальные биржевые котировки из фида рыночных данных моей компании и форматировал их как валюту?»*

1. Часть, требующая обращения к документации: как применить денежную маску формата чисел к диапазону ячеек.
2. Сервер находит соответствующую документацию по форматированию чисел.
3. Поскольку запрос предполагает генерацию кода, он обрабатывается сценарием *Search* (более узкий фактический вопрос вместо этого ушёл бы в *Inference*).
4. *Search* извлекает подходящие страницы из векторного индекса актуальной документации Spreadsheet.
5. Эти страницы возвращаются ассистенту в качестве контекста.
6. Ассистент применяет маску формата, используя этот контекст, а затем самостоятельно пишет логику получения рыночных данных, опираясь на собственные знания, вместо того чтобы гадать насчёт API Spreadsheet.

Результат: генерация кода для Spreadsheet остаётся привязанной к актуальному API формул и форматирования.

## Настройка MCP-сервера в вашем AI-инструменте {#wiring-the-mcp-server-into-your-ai-tool}

Регистрация MCP-сервера выполняется один раз для каждого инструмента — с помощью команды CLI или фрагмента конфигурации JSON, в зависимости от инструмента. В любом случае укажите в вашем инструменте следующий URL:

~~~jsx
https://docs.dhtmlx.com/mcp
~~~

После этого каждый проект Spreadsheet, открытый в этом инструменте, получает доступ к актуальной документации.

Ниже приведены шаги настройки для популярных инструментов.

### Claude Code {#claude-code}

:::info
Claude Code подробно описывает все варианты подключения MCP в [официальной документации](https://code.claude.com/docs/en/mcp).
:::

Чтобы зарегистрировать сервер из командной строки, выполните:

~~~jsx
claude mcp add --transport http dhtmlx-mcp https://docs.dhtmlx.com/mcp
~~~

Для настройки вручную добавьте следующую конфигурацию в файл `.mcp.json`:

~~~jsx
{
  "mcpServers": {
    "dhtmlx-mcp": {
      "type": "http",
      "url": "https://docs.dhtmlx.com/mcp"
    }
  }
}
~~~

### Cursor {#cursor}

:::info
Cursor подробно описывает настройку MCP в [официальной документации](https://cursor.com/en-US/docs/mcp).
:::

Чтобы добавить сервер:

1. Откройте настройки (`Cmd+Shift+J` на Mac, `Ctrl+Shift+J` на Windows/Linux)
2. Перейдите в раздел **Tools & MCP**
3. Нажмите **Add Custom MCP**
4. Вставьте следующую конфигурацию:

~~~jsx
{
  "mcpServers": {
    "dhtmlx-mcp": {
      "url": "https://docs.dhtmlx.com/mcp"
    }
  }
}
~~~

### Google Antigravity {#google-antigravity}

#### Antigravity 2.0 {#antigravity-20}

:::info
Подробности об интеграции MCP-сервера в Antigravity см. в [официальной документации](https://antigravity.google/docs/mcp).
:::

Чтобы подключить MCP-сервер DHTMLX к Google Antigravity, выполните следующие шаги:

1. Откройте палитру команд
2. Введите «mcp add»
3. Выберите «HTTP»
4. Укажите следующие значения:
- Имя:
~~~jsx
dhtmlx-mcp
~~~
- URL:
~~~jsx
https://docs.dhtmlx.com/mcp
~~~

#### Antigravity CLI {#antigravity-cli}

:::info
Если вы переходите с Gemini CLI на Antigravity CLI, см. [соответствующее руководство](https://antigravity.google/docs/gcli-migration#mcp-config-formatting-changes).
:::

Чтобы подключить MCP-сервер DHTMLX к Antigravity CLI, создайте файл `mcp_config.json` в одном из следующих расположений:

- Глобально: `~/.gemini/config/mcp_config.json`
- В рабочей области: `.agents/mcp_config.json`

Добавьте следующую конфигурацию:

~~~jsx
{
  "mcpServers": {
    "dhtmlx-mcp": {
      "serverUrl": "https://docs.dhtmlx.com/mcp"
    }
  }
}
~~~

Затем выполните команду `agy` в терминале.

### ChatGPT {#chatgpt}

:::info
Полное описание настройки MCP-коннектора в ChatGPT см. в [официальной документации](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt).

3. Включите **Developer mode**
4. Вернитесь в **Apps & Connectors** и нажмите «Create»
5. Заполните данные коннектора:
- Имя:
~~~jsx

~~~

~~~jsx
https://docs.dhtmlx.com/mcp
~~~
- Аутентификация: `No authentication`
6. Нажмите **Create**

После создания коннектора ChatGPT получает документацию с MCP-сервера прямо во время разговора.

## Примечания о конфиденциальности данных {#data-privacy-notes}

MCP-сервер работает как размещённый (хостируемый) сервис. Он не запускается локально, не читает файлы из вашего окружения и не хранит персональные данные пользователей.

Запросы могут логироваться в целях отладки и улучшения сервиса.

Организациям, которым требуется более строгий контроль конфиденциальности, доступен коммерческий вариант развёртывания с отключённым логированием запросов. По вопросам обращайтесь по адресу `info@dhtmlx.com`.

## Советы по составлению запросов для работы со Spreadsheet {#prompting-tips-for-spreadsheet-work}

- **Назовите целевой объект.** Различайте экземпляр таблицы, конкретный лист, ячейку и диапазон. Например: «на уровне экземпляра таблицы», «для конкретного диапазона ячеек» или «на листе 2». Чем точнее указана цель, тем легче серверу найти нужные страницы справочника.
- **Указывайте тип ячейки или формат данных.** Запросы вроде «формат даты» или «числовой формат с двумя знаками после запятой» помогают получить более точную документацию, чем обобщённое «ячейка». Указывайте тип всякий раз, когда настраиваете столбцы или применяете форматы.
- **Добавляйте в запрос фразу «Используй документацию».** Она сигнализирует ассистенту, что нужно выполнить обращение к MCP вместо ответа только на основе данных обучения. Это особенно полезно при работе с формулами или проверкой данных, где данные обучения чаще всего устаревают.
- **Чётко указывайте область действия операции.** Операции в Spreadsheet могут применяться к одной ячейке, диапазону, целому столбцу или строке либо ко всему листу. Явно указывайте область действия (например, «для всего столбца B» или «по всем листам»), чтобы ассистент выбрал правильную перегрузку метода или путь API.
